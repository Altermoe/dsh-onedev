# Agent Collaboration Rules

> These rules apply to every coding/agent iteration (`AGENTS.md` → English, `AGENTS.zh.md` → Chinese) that works in this repository. Before making any change, committing, or adding a feature, read and follow them.

## 1. Hard requirement: bilingual documentation

**Every English Markdown document in this project MUST have an equivalent `*.zh.md` (Simplified Chinese) version.** The two must stay consistent and be updated together.

- `README.md` ↔ `README.zh.md`
- `docs/*.md` ↔ `docs/*.zh.md`

Rule checklist:

1. **Paired existence**: any `foo.md` has a `foo.zh.md`, and vice versa. No single-language documents of either kind.
2. **Synchronized edits**: whenever you change or add one language version, update the other **in the same iteration** — never leave a language out of sync.
3. **Content parity**: both documents express the same facts; only the language differs. Commands, tables, paths, tool names, and link targets must not diverge, apart from cosmetic formatting allowed by each language's conventions.
4. **Generated docs**: any document produced by a script (e.g. `docs/tools.md` and `docs/tools.zh.md`) must be regenerated via `npm run docs` — never hand-edit the generated files. When source of truth changes (tool registry, the Chinese map in `scripts/gen-tools-doc.mjs`), re-run and update the generated output.
5. **Count check**: before each commit run a check that every `*.md` has a matching `*.zh.md`.

> The repository-root `README.md` should keep language-switch links at the top (English / 中文).

## 2. Adding a new document

Any new `.md` is not complete until:

1. Write the English version `foo.md`.
2. Immediately write the equivalent Chinese version `foo.zh.md` in **the same commit**.
3. If generated by a script, edit only the source/ generator, run `npm run docs` to produce both, verify, then commit.
4. Update the link lists in the affected docs (e.g. README "further reading") so both language links are present.

## 3. Tool evolution

When adding, renaming, or removing any MCP tool:

1. Edit the tool definition in `src/tools/*` (name, title, description, Zod schema).
2. **At the same time** add/update/delete the tool's Chinese purpose in the `ZH` map in `scripts/gen-tools-doc.mjs`.
3. Run `npm run docs` to regenerate `docs/tools.md` and `docs/tools.zh.md`.
4. If behavior affects docs (API map, integration examples), also update `docs/onedev-api.md` / `docs/onedev-api.zh.md` and `docs/dsh-integration.md` / `docs/dsh-integration.zh.md`.
5. If any tool-count number changes (e.g. "57 tools" in the README), update both README language versions.

## 4. Required checks before every commit

At a minimum run:

```bash
npm run build   # must pass
npm test        # unit + stdio smoke + HTTP smoke, must be green
npm run docs    # regenerate bilingual tool docs
```

Plus the bilingual completeness check (below) — confirm no `*.zh.md` is missing.

## 5. Bilingual completeness check

Run it as a one-shot check, or wire it into CI / an `npm` script:

```bash
# Find every English .md and verify it has a matching .zh.md (repo docs only; skip node_modules)
find . -path ./node_modules -prune -o -name '*.md' -print |
  grep -v '\.zh\.md$' |
  sed 's/\.md$//' |
  while read -r base; do
    [ -f "${base}.zh.md" ] || echo "MISSING zh: ${base}.md"
  done
```

Expected output: nothing. Any `MISSING` line must be fixed before merge.

> Note: `AGENTS.md` itself follows this rule — its Chinese copy is `AGENTS.zh.md`.

## 6. Other conventions

- **Never kill or interrupt a running DSH process/session**; make all changes in the source/files only. No job restarts are needed.
- Keep changes scoped to the current iteration goal; avoid unrelated large refactors.
- Docs ship together with code: any change affecting external behavior must be delivered with its bilingual documentation.
- When a term stays in English (tool names, env-var names, `Bearer`, `stdio`, etc.), keep it consistent in both language versions and explain it in Chinese as needed.

### Progress (session 2026-09-17, fix MCP error spam from the OneDev usage log)

- **Root cause A — `environment` leaked into request bodies (HTTP 400 `Unrecognized
  field "environment"`)**. The per-call routing `environment` param was merged into
  every tool's input schema and then forwarded into the logical args, so tools that
  passed their whole args object as the POST body (`project_create`, `project_update`,
  `role_create`, `role_update`, `access_token_create`) sent `environment` to OneDev,
  which rejected it. **Fix**: `buildServer` in `src/index.ts` now strips `environment`
  once, centrally, before calling `def.run` — the routing metadata never reaches any
  tool body/query again.
- **Root cause B — list tools mis-described the strict `query` grammar (HTTP 406
  `Invalid query`)**. The descriptions promoted invalid examples (`project is "foo"`,
  bare `"dsh"`) that OneDev's criteria parser rejects. **Fix**: `src/tools/types.ts`
  gained `normalizeQuery` (drops blank/whitespace queries) and `withListQueryHint`
  (turns a 406/400 "Invalid query" into a constructive grammar hint). `projects_list`
  and `builds_list` now document valid syntax (`"Name" is "x"`, `"Project"/"Job"/"Version"
  is …`) and use the wrapper.
- **Root cause C — endpoints that do not exist (HTTP 404/405)**.
  * Removed the unbacked `access_tokens_list` (OneDev exposes no global
    `GET /access-tokens`; per-user listing lives in `user_access_tokens`). Tool count
    **61 → 60**; docs/README counts + generated `docs/tools.md`/`.zh.md` updated (also
    `docs/onedev-api` note, `scripts/selftest-docs.mjs`, `scripts/gen-tools-doc.mjs` ZH map).
  * `group_get_id`: `GET /groups/ids/{name}` only exists on newer OneDev; on 404 it now
    falls back to `GET /groups?name=…` + exact match (`resolveGroupId` in `src/tools/groups.ts`).
  * `server_version`: degrades to `{version: null, note}` (not a hard error) on instances
    that lack `/server/version`.
- **Tests**: new `tests/tools-regression.test.mjs` (7 cases) drives the real server over an
  in-memory MCP transport with a mocked fetch — verifies no `environment` in create/update
  bodies, `access_tokens_list` absence, blank-query dropping, the invalid-query grammar hint,
  and `server_version` graceful + success paths. Wired into `npm test`.
- **Verified**: `npm run build`, `npm test` (all suites green, 60 tools over stdio + HTTP),
  both `tsc` typechecks, `npm run docs`, `npm run docs:check` clean, live
  `scripts/selftest-docs.mjs` OK. Live check against real OneDev 16.6.1: `group_get_id`

### Progress (session 2026-09-11, settings persistence UX)

- **Root cause found and fixed**: the config itself was always persisted (the
  credential store at `~/.config/dsh-onedev/config.json`), but
  `POST /api/onedev/probe` ignored the store entirely (`void configFile`).
  Because `GET /api/onedev/config` deliberately never echoes secrets, a
  reopened settings page had blank password/token fields, so every
  "Test connection" failed until the credentials were retyped.
- **Probe now falls back to the store** (`plugin/src/host.ts`): the submitted
  body is merged over the stored config — blank URL/username/token/password
  fields use the stored values, explicitly typed values still win, and the URL
  keeps its `cleanUrl` validation. The probe reply gained `usedStored: string[]`
  naming the fields filled from the store. `apiBase`/`apiTimeoutMs` also fall
  back to the store.
- **Client surfaces the store state** (`plugin/src/client/OneDevSection.tsx`):
  the redacted GET's `passwordSet`/`tokenSet`/`extraHeadersSet` flags now drive
  "Saved — leave blank to keep" placeholders on the secret fields and an
  extra "saved configuration loaded" hint. A successful Save refreshes the
  flags from the returned snapshot and blanks the secret inputs (they are
  persisted, never echoed); Clear resets the whole form; a successful probe
  that used stored secrets reports `testOkStored`.
- **Copy fix**: the section no longer claims "restart dsh to apply" — the MCP
  server re-reads the store on every tool call, matching the READMEs.
  `description`/`saved`/`applyNote` updated in both locales.
- **Tests**: `tests/plugin-host.spec.mjs` covers the probe fallback with a
  local mock OneDev server (asserts the exact `Authorization` header built
  from the stored password/token plus override precedence with an explicit
  password; no external network). The spec is now wired into `npm test` after
  `build:plugin`.

### Progress (session 2025-09-07, documentation-query capability)

- **Added the docs-query MCP capability** (`src/tools/docs.ts`) — three tools
  over the official OneDev documentation at https://docs.onedev.io/:
  - `onedev_docs_search` — full-text search. The site has no public search API
    (its `/search` page is client-side Algolia; `/search-index.json` is an SPA
    fallback), so the tool builds its own index on demand: sitemap → pages →
    `<article>` text. Ranking weights title > path > body hits plus an
    all-tokens and phrase bonus; results carry a text snippet. Non-English
    (CJK) queries fall back to raw substring matching and get a "docs are in
    English" hint when they match nothing.
  - `onedev_docs_read` — one page as readable text: headings (`#`), lists,
    links (absolutized), image alts, fenced code blocks; `related` carries the
    internal doc links found on the page. Accepts a path or a full URL;
    foreign hosts are rejected; unknown paths still fetch (with
    `inSitemap: false`).
  - `onedev_docs_list` — sitemap listing with per-category counts and a
    category substring filter; titles derived from slugs (exact titles via
    read/search).
- **Standalone tools**: `ToolDefinition` gained `standalone?: boolean`
  (`tool(..., { standalone: true })`). In `buildServer` (`src/index.ts`)
  standalone tools skip the per-call config gate and run with a null client —
  docs tools work with zero OneDev credentials, even before the plugin is
  configured. All other tools are unchanged.
- **Index cache**: in-memory per docs-base; sitemap TTL 1 h, page TTL 24 h;
  every tool takes `refresh: true`. Fetch concurrency is capped at 8 with a
  15 s per-request timeout. `ONEDEV_DOCS_URL` (read per call) overrides the
  docs base for mirrors. A SPA-fallback sitemap (HTTP 200 HTML without
  `<loc>`) fails loudly instead of yielding an empty index.
- **Bilingual docs + tests**: ZH map entries in `scripts/gen-tools-doc.mjs`;
  regenerated `docs/tools.md`/`docs/tools.zh.md` (now 60 tools); READMEs in
  both languages updated (counts, feature bullet, env table, tool-reference
  row, testing section); `.env.example` documents `ONEDEV_DOCS_URL`. New unit
  tests `tests/docs.test.mjs` (mocked fetch, no network) wired into `npm test`;
  smoke tests now expect the docs tools; live self-test added at
  `scripts/selftest-docs.mjs`.

### Progress (session 2025-09-07, dsh-onedev → dsh Web settings integration)

- **Package renamed** `@altermoe/dsh-onedev` → `dsh-onedev`. This is **required**:
  the client-modules scanner keys browser modules by the loader specifier, and
  decides a row is a "client package" by walking to the nearest `package.json`
  whose `name` equals the specifier (`locatePkgJson`/`nearestPackage` in
  `packages/client/modules`). A name mismatch silently excluded the plugin from
  the Web boot graph.
- **Added a dsh plugin surface on top of the MCP server**:
  - `plugin/src/host.ts` → `lib/index.js`: a cordis host plugin (`webServer`)
    mounting loopback routes `GET/POST /api/onedev/config`
    (read / save / `clear:true`) and `POST /api/onedev/probe`. Reuses the
    credential store from `src/storage.ts`; secrets are only overwritten when a
    non-empty value is submitted; saves are `0600` + atomic.
  - `plugin/src/client/*` → `lib/client.js`: a Web client plugin registering the
    first-level **OneDev settings section** (`settings.section`, id `onedev`,
    order 120, locale namespace `settings.onedev`) with an administrator
    account/password form, the extra pass-through options, a Test button, and an
    "Open OneDev" quick entry. The client talks to the host routes via
    same-origin `fetch`.
  - Bundle metadata: `dsh.client` manifest (platform `web`), `dsh.bundle.patch`
    → `cordis.patch.yml` (inserts `dsh-onedev` + a `dsh-onedev-mcp`
    `@deepseek-ai/dsh-mcp-client` row with `env: {}`), and the package `main`
    now points to the host plugin while the MCP server stays a `bin`.
- **ONEDEV_URL now comes from the GUI, not the environment.** The MCP server
  resolves its config lazily **per tool call** from env-or-store
  (`buildServer(ConfigProvider)` in `src/index.ts`; `storeProvider` in
  `src/cli.ts`). The credential store written by the settings tab is picked up
  on the next call — no restart, no `ONEDEV_URL` env, and an empty store no
  longer fatals the dsh boot (tools return a friendly "not configured" message).
- **Pass-through parameters added** to `Config`/`StoredConfig`: `apiBase`,
  `transport`, `httpHost`, `httpPort`, `extraHeaders` (env or store; env wins).
  Handled by `src/config.ts`, `src/storage.ts`, `src/setup/server.ts`.
- **Restart helper**: `scripts/restart-dsh.sh` stops/relaunches the `web`
  profile (`pnpm dsh web --no-open`) and waits for readiness.
- **UI aligned to dsh style**: the OneDev section now renders through a
  tokenized, namespaced stylesheet (`plugin/src/client/onedev.css`, injected
  once at apply) using the shared `--dsw-alias-*` tokens — soft 8px inputs,
  18px pill buttons, 16px card radius, the module fill, and the shared focus
  ring. No inline styles or literal colors remain; the bundle is built with
  esbuild (`loader: { '.css': 'text' }`), so the sheet is a scoped global style
  rather than a CSS Module.
- **Profile wiring**: `~/.dsh/profiles/web/package.json` added `dsh-onedev` to
  `dsh.profile.bundles`; `deepseek-harness/dsh-onedev` is a symlink to this
  package.
